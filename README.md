# T-AIR — اطلس هواپیماهای جهان

**T-AIR** سایت جست‌وجوی مشخصات فنی هواپیماهای جهان است — از مسافربری و ملخی کلاسیک
تا جنگنده، بمب‌افکن، ترابری نظامی و آموزشی.
نشان T-AIR یک دم T‌شکل (T-tail) است — پیکربندی دمِ فوکر ۱۰۰، MD-80 و Tu-154،
همان هواپیماهایی که ناوگان مبنای این دیتابیس را ساختند. نام مدل را می‌نویسید (فارسی یا انگلیسی)
و ظرفیت، برد، ابعاد، موتور و پیشینه‌ی آن را می‌گیرید — با تأکید بر مدل‌های رایج در ناوگان ایران.

رابط **دوزبانه** است: فارسی (RTL) و انگلیسی (LTR)، با کلید تعویض زبان در نوار بالا.

**اکنون ۶۵۶ مدل در دیتابیس است** — ۲۱۴ غیرنظامی و ۴۴۲ نظامی، شامل هواپیمای مسافربری،
ملخی کلاسیک، جنگنده، بمب‌افکن، ترابری، بالگرد و پهپاد؛ از ۱۵۶ سازنده،
که ۹۷ فروند از آن‌ها در ناوگان ایران بوده‌اند.

## ساختار پروژه

```
index.html              صفحه‌ی اصلی
assets/styles.css       توکن‌های تم، تایپوگرافی، چیدمان
assets/app.js           جست‌وجو، فیلتر، صفحه‌ی جزئیات
assets/i18n.js          رشته‌های رابط و جدول برچسب‌ها در دو زبان
assets/logo.svg         نشان T-AIR
assets/favicon.svg      آیکون تب مرورگر
data/aircraft.json      دیتابیس (خروجی build_data.py)
scripts/build_data.py   جدول دست‌نویس غیرنظامی + ادغام و اعتبارسنجی
scripts/parts/*.py      جدول‌های داده‌ی تولیدشده + ترجمه‌های انگلیسی (en_*.py)
scripts/merge_parts.py  parts/*.py → military_data.py + civil_extra.py
scripts/build_single.py → dist/ نسخه‌ی تک‌فایلی
scripts/shot.js         تست خودکار با Playwright
```

## قابلیت‌های رابط

- **جست‌وجوی دوزبانه** با پشتیبانی از نگارش‌های مختلف فارسی و اعداد فارسی
- **فیلتر دسته** (غیرنظامی/نظامی)، **گونه** با شمارش زنده، و **پیشران** (ملخی/جت)
- **نمودار دهه‌ی ورود به خدمت** که هم‌زمان شکل مجموعه را نشان می‌دهد و فیلتر دهه هم هست
- **مقایسه‌ی تا سه هواپیما** کنار هم با نشانه‌گذاری بیشترین مقدار هر سطر
- **لینک مستقیم به هر مدل** (`#/boeing-737-800`) با دکمه‌ی کپی لینک و پشتیبانی از دکمه‌ی بازگشت
- **ناوبری با صفحه‌کلید**: `/` برای جست‌وجو، کلیدهای جهت‌دار بین کارت‌ها، `Esc` برای بستن

## دوزبانگی

- **رابط**: همه‌ی رشته‌ها در `assets/i18n.js` زیر `STR.fa` و `STR.en` هستند؛
  برچسب گونه، پیشران، وضعیت و نام کشور هم جدول دوزبانه دارند.
- **داده**: هر رکورد کنار `role` و `armament` و `notes` فارسی، دوقلوی
  `role_en` و `armament_en` و `notes_en` را هم دارد. اگر ترجمه نباشد، رابط
  به متن فارسی برمی‌گردد.
- **جست‌وجو** روی هر دو زبان هم‌زمان ایندکس می‌شود، پس «بویینگ ۷۳۷» و
  «boeing 737» هر دو در هر زبانی کار می‌کنند.

## دو اسکیمای داده

یک جنگنده و یک هواپیمای مسافربری با اعداد یکسانی توصیف نمی‌شوند، پس دو جدول داریم:

- **`CIVIL_COLS`** (۲۴ ستون) — با `seatsTypical` و `seatsMax`
- **`MIL_COLS`** (۲۶ ستون) — با `crew`، `ceilingM`، `armament` و `role`

هر دو در زمان build به یک شکل رکورد واحد با فیلد `category` تبدیل می‌شوند و
فیلدهای بی‌ربط `null` می‌مانند.

## افزودن هواپیمای تازه

سطر تازه را به `scripts/parts/<دسته>.py` یا مستقیم به `CIVIL_ROWS` در
`scripts/build_data.py` اضافه کنید، سپس:

```bash
python3 scripts/merge_parts.py    # parts/*.py را ادغام و تکراری‌ها را حذف می‌کند
python3 scripts/build_data.py     # aircraft.json را می‌سازد و اعتبارسنجی می‌کند
python3 scripts/build_single.py   # نسخه‌های تک‌فایلی در dist/
```

`build_data.py` تکراری‌بودن `id`، درست‌بودن `type` و `status` و `engineKind`،
و منطقی‌بودن اعداد و سال‌ها را بررسی می‌کند و روی خطا build را متوقف می‌کند.

## اجرای محلی

چون داده با `fetch` خوانده می‌شود، فایل را با یک سرور ساده باز کنید:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

یا `dist/t-air.html` را مستقیم در مرورگر باز کنید (همه‌چیز درونش هست).

## انتشار روی GitHub Pages

مخزن را پوش کنید و در Settings → Pages شاخه‌ی `main` و پوشه‌ی `/` را انتخاب کنید.
هیچ مرحله‌ی build لازم نیست.

## نکته‌ها

- **عکس‌ها** هنگام باز شدن کارت از REST API ویکی‌پدیا گرفته می‌شوند (`page/summary`).
  هیچ عکسی در مخزن ذخیره نمی‌شود؛ اگر شبکه در دسترس نباشد سیلوئت جایگزین نمایش داده می‌شود.
- **جست‌وجوی فارسی**: اعداد فارسی/عربی و نگارش‌های مختلف («بوئینگ»، «بویینگ») پشتیبانی می‌شود.
  نگاشت در `SYNONYMS` داخل `app.js` است.
- **داده‌ها** از منابع عمومی سازندگان و دانشنامه‌ها گردآوری شده و برای مرجع سریع است،
  نه برای استفاده‌ی عملیاتی.

## عکس‌ها

سایت بدون عکس هم کار می‌کند: صفحه‌ی جزئیات عکس را در لحظه از ویکی‌پدیا می‌گیرد.
برای اینکه عکس‌ها **داخل مخزن** باشند و همه‌جا — آفلاین، داخل آرتیفکت، پشت فیلتر —
کار کنند، یک بار روی کامپیوتری با اینترنت این را اجرا کنید:

```bash
pip install pillow requests
python3 scripts/fetch_photos.py
python3 scripts/build_single.py
```

اسکریپت برای هر مدل، عکس اصلی مقاله‌ی ویکی‌پدیا را پیدا می‌کند، **فقط** فایل‌هایی را
برمی‌دارد که روی ویکی‌مدیا کامانز میزبانی می‌شوند (چون آن‌ها بنا بر سیاست کامانز
مجوز آزاد دارند، برخلاف عکس‌های fair-use که روی خود ویکی‌پدیا هستند)، نام عکاس و
مجوز را ثبت می‌کند، و سه اندازه می‌سازد:

```
assets/photos/<id>.webp          ۸۸۰px — صفحه‌ی جزئیات
assets/photos/thumb/<id>.webp    ۴۴۰px — کارت نتایج
assets/photos/tiny/<id>.webp     ۱۸۰px — درون فایل تک‌فایلی جاسازی می‌شود
data/photos.json                 نام عکاس، مجوز و لینک هر عکس
```

حدود ۴۰ تا ۵۰ مگابایت می‌شود. اجرا **قابل ازسرگیری** است؛ اگر نیمه‌کاره قطع شد،
دوباره اجرا کنید و از همان‌جا ادامه می‌دهد. مدل‌هایی که عکس آزاد ندارند در
`photos.json` زیر `missing` ثبت می‌شوند تا هر بار دوباره امتحان نشوند.

به‌محض اینکه کتابخانه‌ی عکس ساخته شود، کارت‌های نتایج هم نوار عکس می‌گیرند —
تا آن موقع کارت فشرده‌ی فعلی را نگه می‌دارند.

## اعتبارسنجی و ممیزی

`build_data.py` روی هر build این‌ها را بررسی می‌کند و روی خطا متوقف می‌شود:
یکتابودن `id`، مجازبودن `type` و `status` و `engineKind`، مثبت‌بودن اعداد،
و منطقی‌بودن سال‌ها.

ممیزی داده‌ها به‌صورت **لایه‌ی اصلاحات** ثبت می‌شود، نه ویرایش مستقیم جدول‌ها:
هر فایل در `scripts/fixes/` یک `FIXES = {id: {field: value}}` و در صورت لزوم
`DROP` و `UNRESOLVED` دارد، با توضیح اینکه چه چیزی غلط بوده. تا امروز
۵۷ فیلد اصلاح و ۲ رکورد تکراری حذف شده است.
